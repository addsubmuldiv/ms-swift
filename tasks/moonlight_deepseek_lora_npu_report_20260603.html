MindSpeed 0.15.3 NPU LoRA smoke report: Moonlight and DeepSeek-R1

日期：2026-06-03

这份报告只覆盖 /data/model/Moonlight-16B-A3B-Instruct 和 /data2/model/DeepSeek-R1-BF16。早前 Qwen/FLA 相关临时修改不计入本报告范围。

结论：在 MindSpeed 0.15.3 / Megatron-Core 0.15.3 的 NPU 环境下，Moonlight shared expert LoRA 和 DeepSeek-R1 all-linear LoRA 都已经完成多拓扑 smoke 验证。

公共环境

  • MindSpeed：/data/zyh/code/MindSpeed，core_r0.15.3
  • Megatron-LM：/data/zyh/code/Megatron-LM，core_r0.15.3
  • Python 环境：/data/zyh/miniconda3/envs/swift_dev_v18_swiftpatch
  • 关键环境变量：USE_MCORE_GDN=1、MEGATRON_LM_PATH=/data/zyh/code/Megatron-LM、PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
  • PYTHONPATH 需要包含 mcore-bridge worktree、Megatron-LM、ms-swift worktree，并保留 CANN 原有路径。

整体根因

问题不在 LoRA 数学公式本身，而在 mcore-bridge 原先只覆盖了 Transformer-Engine 风格的线性层，没完整覆盖 MindSpeed/Megatron NPU patch 后出现的 native Megatron parallel linear、NPU TE full-output 语义、grouped LoRA config shape 语义，以及 shared expert overlap 的 explicit communication 状态。

y = x W^T + scale * x A^T B^T

在 tensor parallel 下，LoRA 分支和 base 分支必须返回同一种张量分片：如果 base output 是 sharded，LoRA output 也必须 sharded；如果 base output 是 full tensor，LoRA output 也必须 full tensor。否则 base_result + lora_result 在 shape 或通信语义上都不成立。

Moonlight-16B-A3B-Instruct

现象和根因

Moonlight 脚本目标是 .*.mlp.shared_experts.*.，并开启 moe_shared_expert_overlap。shared experts 里的目标层是 Megatron native ColumnParallelLinear / RowParallelLinear，不是 PEFT 默认支持的普通 torch.nn.Linear。

MindSpeed 会把 shared expert 的 TP/SP 通信交给外部 overlap 流程控制。LoRA adapter 新建的 A/B 层如果不继承 base layer 的 explicit_expert_comm 等状态，就会按普通 parallel linear 做通信，最终在 token 维度或 hidden 分片上和 base output 不一致。

修复点

  • swift/megatron/trainers/base.py：对 save_safetensors=true、tuner_type=lora、merge_lora=true 且目标模块来自 regex 的场景，跳过中间 PEFT adapter save，让 merged full-weight HF export 继续完成。
  • src/mcore_bridge/config/model_config.py：保留 rope_scaling.rope_type 到 ModelConfig.rope_type。
  • src/mcore_bridge/tuners/patcher.py：把 ColumnParallelLinear / RowParallelLinear 加进 LoRA dispatcher 支持类型。
  • src/mcore_bridge/tuners/lora.py：为 native row/column parallel linear 构造数学上匹配的 LoRA A/B；关闭 adapter 的 gradient accumulation fusion；继承 explicit_expert_comm，保持 shared expert overlap 通信语义一致。

DeepSeek-R1-BF16

现象和根因

DeepSeek-R1-BF16 使用 DeepSeekV3-style 结构，smoke 目标是 --target_modules all-linear。在更高 TP/PP/EP 拓扑下，部分 NPU TE patched layer 在 TP>1 时仍返回 full output，而不是普通 column-parallel 的 per-partition output；同时 grouped LoRA 的 config hidden size 也需要等于 adapter 的真实输入维度。

如果 LoRA adapter 仍按普通 TE column-parallel 或原始 model hidden size 构造，就会得到数学上不匹配的 adapter shape。

修复点

  • src/mcore_bridge/tuners/lora.py：增加 _base_outputs_full_tensor()，检测 NPU patched base layer 是否返回 full output；如果 base 是 full output，LoRA B 也构造成本地 full-output adapter。
  • src/mcore_bridge/tuners/lora.py：增加 _with_lora_input_size()，为 grouped LoRA A/B 拷贝 config 并设置真实 adapter input size。
  • src/mcore_bridge/tuners/lora.py：对旧 NPU/无 TE 场景保留 nn.Linear fallback；对 parallel_mode / UB overlap 属性使用 guard。
